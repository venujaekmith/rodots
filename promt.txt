### 2. High-Efficiency Data Structures & Algorithmic Engine
Implement the navigation brain using these five core data structures and algorithms:

1. **Explicit DFS Decision Stack (`list` as LIFO Stack) — Decision Recording & Undo:**
   * Every time `eLLo` commits to a branch at a junction, push a decision frame onto `decision_stack`:
     `DecisionFrame(node_id, entry_dir, chosen_exit_dir, edge_distance_m)`
   * **Undo & Backtrack Protocol:** When a branch fails (either `front_obstacle_sensor` detects a rock ahead or the black guide line terminates in a dead end), execute an immediate rollback:
     1. Stop motors safely before rock contact[cite: 6].
     2. Pop the top `DecisionFrame` from `decision_stack`.
     3. Mark `graph[node_id].exits[chosen_exit_dir] = BLOCKED` in $O(1)$ time.
     4. Execute a closed-loop $180^\circ$ pivot turn onto the reverse cardinal heading, reacquire the black line, and follow it back to `node_id`[cite: 6].
     5. At `node_id`, select the next `UNEXPLORED` exit (prioritizing branches aligned toward the general maze frontier) and push the new decision frame onto `decision_stack`.

2. **Spatial-Hashed Topological Graph (`dict` + Grid Bucketing) — $O(1)$ Loop & Cycle Prevention:**
   * Because K-391 layouts contain cyclic loops, pure DFS without cycle detection will loop infinitely.
   * Represent the maze as an adjacency hash map: `nodes[node_id] = Node(x, y, exits={dir: UNEXPLORED | BLOCKED | (neighbor_id, edge_cost)})`.
   * Index nodes into a spatial grid hash (`grid_buckets[(int(x // cell_size), int(y // cell_size))]`) and check the $3 \times 3$ neighborhood within `NODE_MERGE_RADIUS` for $O(1)$ amortized node lookup.
   * When arriving at a junction whose coordinates match an existing `node_id`, link the bidirectional edge with its measured encoder `edge_cost` (in meters), mark the arrival direction as explored, and avoid re-traversing already explored loops unless required for transit.

3. **A\* / Dijkstra Weighted Shortest-Path Planner (`heapq` Min-Heap) — Checkpoint Sprinting:**
   * Maintain a hash map `checkpoint_memory[color] = node_id` for any checkpoint encountered during exploration[cite: 6, 7].
   * Whenever a checkpoint is confirmed and the target advances (e.g., `GREEN` $\rightarrow$ `RED`), immediately check `checkpoint_memory[new_target]`:
     * **If already discovered:** Run **A\* search** (using `heapq` with Euclidean distance heuristic and actual recorded `edge_cost` weights) from the current `node_id` to `checkpoint_memory[new_target]`, overriding exploration to sprint straight to the target along the shortest known path[cite: 6, 7].
     * **If not yet discovered:** Use **Dijkstra / Nearest-Frontier search** to find the minimum-distance path to the closest junction that still has an `UNEXPLORED` exit.

4. **O(1) Ring-Buffer Sensor Filters (`collections.deque(maxlen=N)`):**
   * Filter `front_obstacle_sensor` with a 3-sample median buffer so single-step sensor noise never triggers false obstacle reversals.
   * Filter downward camera RGB readings with a 3-frame majority-vote buffer so transient color noise never causes false checkpoint triggers or missed pads.

5. **Landmark Odometry Drift Correction (Pose Snapping):**
   * Track $(x, y, \theta)$ continuously from `left_wheel_encoder` and `right_wheel_encoder`[cite: 5].
   * Snap $\theta$ gently toward the nearest cardinal axis ($0^\circ, 90^\circ, 180^\circ, 270^\circ$) during long straight line-following segments, and blend $(x, y)$ toward stored node coordinates upon revisiting a mapped junction to eliminate long-run encoder drift.

### 3. Low-Level Motion, Line Tracking & Recovery Control
* **Auto-Calibration on Startup:** Dynamically read `getMaxVelocity()` from the motors, infer `front_obstacle_sensor` scale (meters vs. raw proximity), and learn IR floor-vs-black-line polarity/contrast dynamically so the controller adapts automatically across unseen evaluation worlds[cite: 6].
* **Curvature-Adaptive Weighted-Centroid PID:** Compute continuous line error across all 7 IR sensors (`weights = [-3, -2, -1, 0, +1, +2, +3]`). Modulate forward speed smoothly between `CRUISE_SPEED` (on straightaways, maximizing the time-efficiency score $5 \times (1 - t/1200)$) and `MIN_CURVE_SPEED` (on sharp $90^\circ$ bends) so `eLLo` hugs ~4 cm curves without overshooting[cite: 4, 8].
* **Curve vs. Intersection Classification:** Do not create graph nodes on simple $90^\circ$ bends. Only trigger junction logic when wide outer IR sensors activate (`ir_line_0..2` or `ir_line_4..6`), step forward ~5 cm to check whether the straight path continues, and create a junction node only when $\ge 2$ outgoing branches exist (T-junction or crossroad)[cite: 3, 4, 6].
* **Bounded Line-Loss Recovery:** If all 7 IR sensors lose the line temporarily, execute a bounded sweep toward `last_seen_side`. If the line is not reacquired within a strict step limit and no junction is present, treat it as a dead end or trigger a safe emergency stop rather than spinning indefinitely or driving off-track[cite: 6, 7].
